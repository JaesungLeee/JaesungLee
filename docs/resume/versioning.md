# 경력기술서 버전 규칙

수정본은 항상 **새 Google Docs 문서**로 저장한다. 이전 버전 문서는 건드리지 않는다.

## 파일명

`{파일명 접두어}{major}.{patch}` (예: `..._경력기술서_v.2.1`, v 뒤에 점이 있다)

파일명 접두어는 `private/profile.md`에 있다.

## 버전 올리기

| 구분 | 조건 | 예시 |
|---|---|---|
| major | 새 프로젝트·항목 추가, 또는 한 섹션 이상을 다시 쓴 경우 | `v.2.1` → `v.3.0` |
| patch | 오타 수정, 표현 다듬기, 수치 갱신 같은 작은 수정 | `v.2.1` → `v.2.2` |

- 변경 중 하나라도 major면 major로 올린다. major를 올리면 patch는 0으로 돌아간다.
- 리뷰 제안을 반영할 때는 제안 표의 "버전 영향" 열을 따른다 ([review-criteria.md](review-criteria.md)).
- 새 문서를 만들기 전에 **항상** 버전과 변경 내용을 사용자에게 확인받는다.

## 공고 맞춤본

특정 채용공고에 맞춰 고친 문서는 버전 관리 대상이 아니다.

- 저장 위치: `private/profile.md`의 **공고 맞춤본 폴더** (메인 버전 폴더 아래 하위 폴더)
- 파일명: `{이름}_경력기술서_{회사명}` (예: `..._경력기술서_KREAM`). 버전 번호를 붙이지 않는다.
- 기준 문서: 항상 메인 폴더의 최신 버전을 복사한다.
- 버전 번호를 올리지 않고, "최신 버전" 판정에서도 빠진다. 다음 수정은 계속 메인 최신 버전에서 시작한다.
- 같은 회사 파일이 이미 있으면 덮어쓰거나 수정하지 않는다. 사용자에게 알리고 `_2`, `_3`을 붙인 새 이름을 제안한다.
- 기록은 `private/CHANGELOG.md`의 "공고 맞춤본" 섹션에 남긴다.
