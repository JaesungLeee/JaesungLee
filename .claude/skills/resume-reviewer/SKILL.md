# resume-reviewer

경력기술서를 읽고 평가만 한다. **Google Drive 파일을 만들거나, 복사하거나, 수정하거나, 휴지통으로 보내지 않는다.** 반영은 resume-update가 맡는다.

## 입력

- 버전 (선택): 없으면 최신 버전을 본다. 예: `v.2.0`
- 채용공고 (선택): URL이나 텍스트. 있으면 공고 맞춤 리뷰를 함께 한다.
- 검수 대상 초안 (resume-update가 호출할 때만): 바뀐 섹션의 수정안 텍스트

## 개인 설정 불러오기 (항상 먼저)

1. `docs/resume/private/profile.md`를 Read로 읽어 **파일명 접두어**, **Drive 폴더 id**, **버전 관리 제외 파일**을 가져온다. 아래에서 `{파일명 접두어}`, `{폴더 id}`는 이 값을 뜻한다.
2. 파일이 없으면 여기서 멈춘다. `docs/resume/private.example/`를 `docs/resume/private/`로 복사해 값을 채우라고 안내한다.
3. `docs/resume/private/`는 gitignore되어 있다. Glob/Grep 검색에 안 잡힐 수 있으니 항상 정확한 경로로 Read한다.

## 참고 문서

리뷰를 시작하기 전에 모두 읽는다.

- `docs/resume/review-criteria.md`: 평가 기준, 심각도, 지킬 것, 알려진 사실, 출력 형식. **판단은 이 문서를 따른다.**
- `docs/resume/private/examples.md`: 기준을 실제 이력서에 적용한 사례(판단 기준점), **알려진 사실**, 형식 현황
- `docs/resume/style-guide.md`: 형식 규칙. 표기·서식이 맞는지 볼 때 쓴다.
- `docs/resume/private/reviews/` 의 가장 최근 리뷰: 지난번 제안 중 아직 반영되지 않은 것을 찾는 데 쓴다.

## 절차

### 1. 대상 문서 찾기

1. Drive `search_files`로 `parentId = '{폴더 id}'`인 폴더에서 `title contains '{파일명 접두어}'`를 찾는다.
2. 제목에서 `_v.(\d+).(\d+)`로 major, patch를 뽑는다. 이 형식이 아닌 파일(profile.md의 버전 관리 제외 파일 등)은 제외한다.
3. 숫자로 비교해서 가장 높은 버전을 고른다. 문자열 비교는 하지 않는다 (`v.2.10` > `v.2.9`).
4. 버전을 지정받았으면 그 버전을 고른다. 없으면 사용자에게 버전 목록을 보여 주고 묻는다.

### 2. 읽기

- `read_file_content`로 본문을 읽는다. 문서에 달린 코멘트도 보려면 `includeComments: true`를 쓴다.

### 3. 평가

`review-criteria.md`의 순서대로 본다.

1. `private/examples.md`의 "알려진 사실"을 먼저 확인한다. 이미 확인된 사실은 지적하지 않고 대응 방안을 제안한다.
2. 섹션 간 관계: 위쪽 섹션의 주장마다 아래쪽에 근거가 있는지 본다.
3. 공통 기준, 섹션별 기준을 차례로 적용한다. Work Experience는 항목마다 유형을 분류하고 필수 요소를 체크한다.
4. 제안이 "지킬 것"의 강점을 깨지 않는지 확인한다.
5. 지난 리뷰의 제안 중 아직 반영되지 않은 것을 표시한다.

### 4. 공고 맞춤 리뷰 (채용공고가 있을 때)

출력의 "제안" 앞에 다음 섹션을 추가한다.

```markdown
## 공고 매칭
| 공고 요구사항 | 이력서 근거 | 상태 |
|---|---|---|
| Jetpack Compose 실무 경험 | Work Experience > Compose 성능 최적화 | 충분 / 보강 필요 / 없음 |

- 빠진 키워드: ...
- 앞으로 올리거나 강조할 항목: ...
```

공고 때문에 생긴 제안은 "섹션" 칸에 `[공고]`를 붙인다.

### 5. 출력과 저장

- `review-criteria.md`의 "출력 형식"을 그대로 따른다. "제안 작성 규칙"을 지킨다. 특히 없는 수치는 지어내지 않고 `[확인 필요: ...]`로 둔다.
- 단독 첨삭일 때는 결과를 `docs/resume/private/reviews/YYYY-MM-DD_v.X.Y.md`로 저장한다. 같은 이름이 있으면 `_2`, `_3`을 붙인다. 공고 맞춤 리뷰면 파일명 끝에 `_jd-회사명`을 붙인다.
- 저장한 뒤 사용자에게 요약(높음 심각도 제안, 확인 필요 항목)을 보여 주고, 반영하려면 resume-update에 번호를 주면 된다고 안내한다.

## 자동 검수 모드 (resume-update가 호출할 때)

- 문서 전체가 아니라 **초안으로 받은 변경 부분**만 평가한다. 다만 같은 섹션의 기존 항목과 형식·문체가 맞는지는 함께 본다.
- 새 항목이면 `style-guide.md`의 해당 섹션 템플릿과 비교한다.
- 결과는 파일로 저장하지 않고 "제안" 표와 "확인 필요" 목록만 돌려준다. 문제가 없으면 "수정 제안 없음"이라고 쓴다.
